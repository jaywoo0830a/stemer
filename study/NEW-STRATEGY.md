### 🏭 전체 아키텍처 요약: 수학 교재 생성 RAG 공장

#### 1. 하드웨어 및 소프트웨어 스택
- **서버 (팩토리)**: 9700X (8코어), 64GB RAM
  - 역할: 벡터DB 저장, 검색, 프롬프트 엔지니어링, 병렬 워커 관리.
- **AI 엔진**: DeepSeek Flash API (OpenAI 호환 프로토콜)
  - 역할: 실제 교재 텍스트 생성, 자동 캐싱 수행.

---

#### 2. 사전 준비 과정 (오프라인, 최초 1회 실행)
- **수집**: 수십 권의 수학 교재 PDF/TXT를 서버에 적재.
- **가공**: 텍스트를 300~500토큰 단위로 분할(Chunking).
- **색인화**: 분할된 청크를 임베딩 모델로 벡터화하여 **벡터 DB(ChromaDB 등)**에 저장.
- **고정 프롬프트 설계**: 시스템 프롬프트 + 핵심 공식/개념 종합 가이드(약 2,000~8,000토큰)를 **절대 바꾸지 않을 상수**로 정의.

---

#### 3. 실시간 요청 처리 파이프라인 (사용자 요청 -> 결과 도출)

| 단계 | 주체 (서버 vs API) | 수행 액션 |
| :--- | :--- | :--- |
| **① 입력** | **서버** | 사용자로부터 *"Sequence(수열) 토픽 생성"* 요청을 수신. |
| **② 검색** | **서버** | 요청어를 임베딩하여 벡터DB에서 관련도 높은 상위 3~5개 조각(수열 정의, 점화식, 예제 등)을 검색. (멀티코어 활용) |
| **③ 조립** | **서버** | **[고정 A (시스템 프롬프트)] + [고정 B (거대 개념 가이드)] + [가변 C (방금 검색된 3개 조각)] + [가변 D (사용자 질문)]**<br>을 하나의 거대 프롬프트로 조립 (총 약 3,000~10,000 토큰). |
| **④ 전송** | **서버** | 조립된 프롬프트를 DeepSeek Flash API `/chat/completions`로 HTTP POST 전송. (비동기 `asyncio` 사용) |
| **⑤ 캐싱** | **API** | 프롬프트 앞부분(**A+B**)이 동일함을 확인 → **하드 디스크 캐시 히트** (수 시간~며칠간 유효).<br>해당 부분은 새로 계산하지 않고 캐시에서 즉시 재사용. |
| **⑥ 생성** | **API** | 캐시된 컨텍스트 + 새로운 가변 부분(C+D)을 참조하여 GPU로 교재 내용을 생성(스트리밍 가능). |
| **⑦ 반환** | **API -> 서버** | 생성된 LaTeX/텍스트 교재를 JSON 형식으로 서버에 반환. |
| **⑧ 저장** | **서버** | 결과를 디스크에 `.md` 또는 `.tex` 파일로 저장하고 사용자에게 출력. |

#### 4. 성능 및 비용 최적화 전략 (멀티코어 활용)

- **병렬 처리 (멀티스레딩)**: 
  - "수열, 함수, 미분" 등 여러 토픽을 동시에 요청하면, 서버는 8코어를 활용해 **N개의 워커(Thread)**를 띄워 벡터 검색과 API 호출을 동시에 수행.
  - DeepSeek Flash의 동시 요청 한도(2,500) 내에서 최대한 병렬로 쏴서, 1개 생성 시간(30초)과 10개 생성 시간(35초)을 거의 동일하게 만듦.
  
- **비용 절감 — 실단가 기준 (DeepSeek Flash · 오프피크)**:
  - **실단가**: 입력 캐시 히트 **$0.007/M** · 입력 캐시 미스 **$0.22/M** · 출력 **$0.66/M**. 피크 시간대는 전부 ×2.
  - **프리픽스 캐시**: 고정부 A+B가 동일하면 API가 자동 캐시 → 해당 입력 구간은 $0.007/M (미스 대비 **~1/31**).
    OpenAI 호환 API는 자동 프리픽스 캐싱이라 별도 `cache_control` 파라미터가 필요 없다.
  - **중요 — 비용의 지배 요인은 출력 토큰**: 노트 1편(출력 ≈ 4,000토큰) 기준 출력 비용 ≈ **$0.0026** (전체의 ~85%).
    캐싱은 입력 비용만 줄이므로 총비용 절감 한계는 ~20~30%. → 실질 절감은 **출력 토큰 통제**에서 나온다.
    상세: [`GEN-PROTOCOL.md`](GEN-PROTOCOL.md).

#### 5. 기대 효과 (최종 아웃풋)

| 항목 | 기존 (순수 API 호출) | 개선 후 (RAG 공장) |
| :--- | :--- | :--- |
| **비용** | 입력 미스 $0.22/M + 출력 $0.66/M (전부 정가) | 입력 캐시 히트 $0.007/M (미스 대비 ~1/31) · 출력은 캐시 불가 → **출력량 통제가 핵심** |
| **속도** | 매번 긴 컨텍스트를 새로 계산 (느림) | 캐시 재사용으로 **TTFT(첫 토큰 도달 시간) 대폭 단축** |
| **정확도** | AI가 교재 내용을 환각(Hallucination) | **검증된 실제 교재 조각**을 참조하므로 환각 90% 감소 |
| **동시성** | 순차 처리로 대기 시간 발생 | **8코어 병렬 처리**로 대량 교재 생성 시간 압축 |

**실단가 기반 토픽당 비용 (오프피크)**: 입력(캐시 히트 위주) ≈ $0.0005 + 출력(4,000토큰) ≈ $0.0026
→ **≈ $0.003/토픽**. 출력을 프로토콜 예산(≈1,500토큰)으로 통제하면 **≈ $0.001~0.0015/토픽**.
1,000토픽 ≈ **$1~3** (피크는 ×2 → 배치는 오프피크에).
